# edu-llm — своя учебная LLM с нуля

Маленький GPT (decoder-only трансформер) примерно на 300 строк PyTorch:
токенизатор, модель, обучение и генерация. Его можно прочитать целиком за вечер,
обучить на ноутбуке и увидеть, как модель переходит от случайных символов
к связному тексту.

> **Чего ожидать.** Архитектура та же, что у GPT-2/3, только в масштабе ~1 млн
> параметров вместо миллиардов. Она выучит орфографию, стиль и ритм текста,
> на котором её обучали, но фактов знать не будет и разговаривать не сможет.
> Цель — **понять, как устроены LLM**, а не заменить ChatGPT.

## 1. Окружение

Нужны Python 3.9+ и PyTorch. GPU не обязателен.

**Вариант A — локально (Linux / macOS / WSL):**
```bash
cd edu-llm
./setup.sh            # CPU-версия PyTorch; для NVIDIA GPU: ./setup.sh gpu
source .venv/bin/activate
```

**Вариант B — Docker** (ничего не ставится на систему):
```bash
docker build -t edu-llm .
docker run --rm -it -v "$PWD":/app edu-llm bash
```

**Вариант C — Google Colab** (бесплатный GPU): Runtime → Change runtime type → T4 GPU, затем
```python
!git clone https://github.com/kirshp/kirshp

!python prepare_data.py && python train.py --n_layer 6 --n_embd 384 --n_head 6 --block_size 256 --batch_size 64 --max_iters 5000 --lr 6e-4
```

## 4. Теория

### 4.1 Языковая модель = предсказатель следующего токена

LLM решает одну задачу: по началу текста выдать распределение вероятностей
следующего токена. Вероятность всего текста раскладывается в произведение:

```
P(t₁, t₂, …, tₙ) = P(t₁) · P(t₂ | t₁) · P(t₃ | t₁,t₂) · … · P(tₙ | t₁…tₙ₋₁)
```

Генерация — это цикл: предсказали распределение → выбрали из него токен →
дописали его в конец → повторили (`GPT.generate`). Всё «понимание» у модели
появляется только потому, что предсказывать следующее слово хорошо без понимания
контекста невозможно.

### 4.2 Токенизация

Нейросеть работает с числами, поэтому текст режется на токены, а каждый токен
получает номер. Здесь токен — один символ (словарь из 65 символов для Шекспира,
~150 для русского текста). Настоящие модели используют **BPE**: начинают с
символов (байтов) и склеивают самые частые пары в новые токены, пока словарь не
вырастет до 30–200 тыс. Тогда «привет» — это 1–2 токена, а не 6, и в то же окно
контекста помещается в разы больше текста.

### 4.3 Эмбеддинги

Номер токена превращается в обучаемый вектор длины `n_embd` (строка матрицы
`tok_emb`). Внимание само по себе не знает порядка слов, поэтому к вектору
прибавляется вектор позиции (`pos_emb`). Дальше модель работает с
тензором `(batch, T, n_embd)`: по вектору на каждую позицию.

### 4.4 Self-attention — главная идея трансформера

Каждая позиция должна собрать информацию из предыдущих. Для каждого вектора `x`
считаются три линейные проекции:

- **q** (query) — что эта позиция ищет;
- **k** (key) — что эта позиция может предложить;
- **v** (value) — что она отдаст, если её выберут.

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d  +  mask ) · V
```

`Q·Kᵀ` — матрица «насколько позиция i заинтересована в позиции j».
Деление на `√d` не даёт softmax насыщаться. **Каузальная маска** ставит `−∞`
выше диагонали: позиция i видит только 0…i, иначе при обучении модель просто
подсмотрела бы ответ. Softmax превращает строки в веса, которые в сумме дают 1,
а результат — взвешенная сумма векторов `v`.

**Multi-head:** вектор делится на `n_head` частей, и у каждой головы своё внимание.
Одна голова может следить за предыдущей буквой, другая — за началом слова,
третья — за открытой кавычкой. Выходы склеиваются и смешиваются матрицей `proj`.

### 4.5 Трансформер-блок

```
x = x + Attention(LayerNorm(x))   # токены обмениваются информацией
x = x + MLP(LayerNorm(x))         # каждый токен обрабатывает её сам
```

- **MLP**: `Linear(d → 4d) → GELU → Linear(4d → d)`. Здесь хранится основная
  часть «знаний» модели, и здесь же около 2/3 её параметров.
- **Residual-связи** (`x + …`) дают градиенту прямой путь через десятки слоёв;
  без них глубокие сети почти не обучаются.
- **LayerNorm** нормирует векторы и стабилизирует обучение.

Блок повторяется `n_layer` раз. В конце последний LayerNorm и `head`: проекция в
`vocab_size` чисел (логитов), по одному на каждый возможный следующий токен.
Матрица `head` общая с `tok_emb` (**weight tying**) — это экономит параметры.

### 4.6 Функция потерь и что означают числа

Обучающий пример — кусок текста `x` и тот же кусок, сдвинутый на 1 символ, `y`.
Модель предсказывает следующий токен **в каждой позиции сразу**, поэтому один
кусок длиной 128 даёт 128 обучающих примеров.

Потери — **кросс-энтропия**: `−log P(правильный токен)`, усреднённая по позициям.

- В начале loss ≈ `ln(65) ≈ 4.17`: модель угадывает равномерно среди 65 символов.
  Если на шаге 0 вы видите сильно другое число, скорее всего, что-то не так с инициализацией.
- loss 1.5 ≈ `e^1.5 ≈ 4.5`: модель в среднем выбирает примерно из 4–5 вариантов (**perplexity**).
- **train loss** считается на 90% текста, **val loss** — на 10%, которые модель
  не видела. Если train падает, а val растёт, модель **переобучается**:
  запоминает текст, а не обобщает. Лекарства — больше данных, больше `dropout`, меньше модель.

### 4.7 Обучение

Один шаг: прямой проход → loss → `loss.backward()` (backpropagation считает
градиент по каждому параметру) → `optimizer.step()` (сдвигает параметры против градиента).

- **AdamW** — Adam (своя адаптивная скорость для каждого параметра) плюс weight
  decay (слабо тянет веса к нулю, это регуляризация).
- **Warmup + cosine decay**: learning rate сначала плавно растёт (в начале
  градиенты шумные), потом плавно падает (в конце нужны мелкие точные шаги).
- **Gradient clipping** обрезает редкие огромные градиенты, чтобы не «взорваться».

### 4.8 Генерация: temperature и top-k

- **temperature** делит логиты перед softmax. `< 1` — распределение острее,
  текст осторожнее и однообразнее; `> 1` — площе, «креативнее» и безумнее; `→ 0` — всегда самый вероятный токен.
- **top-k** оставляет только k самых вероятных токенов и отрезает хвост мусора.

### 4.9 Масштаб: от игрушки к GPT

Параметров примерно `12 · n_layer · n_embd²` (плюс эмбеддинги).

| Модель | n_layer | n_embd | Параметры | Данные |
|--------|---------|--------|-----------|--------|
| edu-llm (по умолчанию) | 4 | 128 | 0.8 M | 1 МБ |
| edu-llm на GPU (из раздела про Colab) | 6 | 384 | 10.8 M | 1 МБ |
| GPT-2 small | 12 | 768 | 124 M | 40 ГБ |
| GPT-3 | 96 | 12288 | 175 B | ~300 млрд токенов |

**Законы масштабирования:** loss предсказуемо падает с ростом параметров,
данных и вычислений. Практическое правило Chinchilla — около **20 токенов данных
на параметр**. Отсюда и пределы учебной модели: 1 МБ текста хватает на модель в
несколько миллионов параметров, но не больше.

### 4.10 От базовой модели к ассистенту

То, что обучается здесь, — **базовая (pretrained) модель**: она продолжает
текст. Чтобы получить ассистента, делают ещё два шага:

1. **SFT (supervised fine-tuning)** — дообучение на диалогах «вопрос → хороший ответ».
2. **RLHF / DPO** — дообучение на предпочтениях: из двух ответов люди (или
   другая модель) выбирают лучший, и модель сдвигают в сторону лучших.

Архитектура при этом не меняется: те же `model.py` и `train.py`, только другие данные и функция потерь.

## 5. Упражнения

1. **Базовая линия.** Поставьте `--n_layer 0` и посмотрите, до какого loss
   дойдёт модель без внимания. Это почти биграммная модель.
2. **Роль маски.** Уберите `masked_fill` в `CausalSelfAttention`: train loss
   провалится почти до нуля, а генерация сломается. Объясните, почему.
3. **Переобучение.** Возьмите маленький текст (~50 КБ) и модель побольше —
   поймайте момент, когда val loss начинает расти.
4. **Temperature.** Сгенерируйте текст с `--temperature 0.3`, `1.0` и `1.5` и сравните.
5. **Размер контекста.** Сравните `--block_size 32` и `256`: на каком расстоянии
   модель «держит» структуру (рифму, имя персонажа)?
6. **Русский язык.** Обучите на русских классиках и сравните словарь и loss с Шекспиром.
7. **BPE.** Замените `CharTokenizer` на `tiktoken` (`pip install tiktoken`,
   кодировка `gpt2`) и уменьшите `block_size`: что изменилось?
8. **Скорость.** Замените ручное внимание на `F.scaled_dot_product_attention(q, k, v, is_causal=True)`
   и замерьте ускорение.
9. **Визуализация.** Сохраните матрицу `att` из одной головы и нарисуйте её
   heatmap-ом: куда смотрит модель?
